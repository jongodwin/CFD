# Mass Balance Reconciler

A browser app that reconciles redundant mineral processing sample data into a
consistent mass balance. It adjusts measured flows, size distributions and assays
as little as possible (weighted by their estimated errors) so that every unit in
the circuit conserves mass, and reports a standard deviation for every
reconciled value.

No install, no build, no server: open `index.html` in a browser. The app starts
with an example grinding and flotation circuit.

## What it does

- **Data options, in any combination** (Setup tab)
  - particle size distribution (mass % retained per size fraction)
  - chemical head assays
  - assays of each individual size fraction
- **Node network, drawn or tabulated** (Flowsheet tab). Draw units and streams on
  the flowsheet, or edit the same network in the Units and Streams tables. A
  stream with an open end is a feed or a product.
- **Units that keep or change the size distribution.** A classifier, splitter,
  flotation bank or sump balances every size fraction (and every component in
  every size fraction). A mill or crusher balances only total solids and total
  component mass.
- **Relative error per stream** (Sample data tab) for flow, size, head assay and
  size-fraction assay measurements, plus a smallest absolute error per component
  and for size fractions so near-zero values are not treated as exact. Blank
  cells are unmeasured.
- **No negative flows.** See the method below.
- **Results**: reconciled value, its standard deviation and the original
  measurement for every flow, size fraction, head assay and size-fraction assay
  on every stream. Cells adjusted by more than 2 or 3 measurement standard
  deviations are flagged, the largest adjustments are listed, and the fit
  summary gives the weighted sum of squares against the redundancy. Results copy
  to a spreadsheet or download as CSV. Projects save and load as JSON.

## Method

The unknowns are mass flows, not ratios: solids flow in each size fraction of
each stream, and component flow (per size fraction if size-fraction assays are
used). With that choice:

- every node balance is an exact linear equation, `A x = 0`;
- "no negative flows" is the bound `x > 0`, enforced with a logarithmic barrier
  (interior-point method), so an inconsistent sample drives a flow toward zero
  rather than below it;
- each measurement is a ratio of sums of unknowns (a size fraction is
  `m_i / Σm`, an assay is `c / m`), and the solver minimises
  `Σ ((model − measured) / σ)²` with a damped Gauss–Newton iteration on the null
  space of `A`, so every iterate conserves mass exactly.

Standard deviations of the reconciled values come from propagating the
measurement errors through the constrained least-squares solution (the inverse
of the reduced Gauss–Newton matrix, mapped to each reported quantity with the
delta method). Values that the data cannot determine are reported as "n.d."
instead of a number.

The solver is `js/solver.js` and has no dependencies; it also runs in Node:

```js
const { reconcile } = require('./js/solver.js');
const result = reconcile(project); // same JSON as the app's project file
```

## Tests

```
node --test test/solver.test.js
```

The tests check that exactly balanced data is reproduced for each combination of
data options, that balances close on noisy data, that predicted standard
deviations match the scatter of 300 Monte Carlo reconciliations, that flows stay
non-negative when the assays imply a negative split, and that undeterminable
values and input errors are reported.
